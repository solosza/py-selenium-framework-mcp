# 4D Framework Workflow

Structured workflow: Design → Define → Divide → Deliver with adversarial checkpoints.

## Instructions

**Step 1: Classify Work Type**

Ask user:
```
WORK TYPE

1. New feature/capability
2. Fix/change existing code (will include impact assessment)

Select (1-2):
```

Store selection. If FIX selected, `/fix` impact assessment will be required in Deliver phase.

**Step 2: Select Phases**

Ask user:
```
WHICH PHASES DO YOU NEED?

[ ] 1. Design  - Explore direction, approaches, constraints
[ ] 2. Define  - Create PRD/spec with requirements
[ ] 3. Divide  - Break into tasks with done-when criteria
[ ] 4. Deliver - Implement with TodoWrite tracking

Select phases (e.g., "3,4" or "all"):
```

Create TodoWrite entries for selected phases.

---

## Phase Execution

Execute only selected phases in order. Each phase follows its template.

---

### PHASE 1: DESIGN

**Template:** Read `docs/1-design-discussion-v2.md`

**Execute:**
- Conversational exploration per template
- Discuss direction, constraints, trade-offs
- Document key decisions

**Grill:**
```
DESIGN REVIEW

Grilling this direction...
- What's wrong with this approach?
- What constraints are we ignoring?
- What will we regret later?

[Provide critical analysis]
```

**HITL Checkpoint:**
```
DESIGN COMPLETE

1. Continue to next phase
2. Refine direction (discuss more)
3. Pause here

Select (1-3):
```

---

### PHASE 2: DEFINE

**Template:** Read `docs/2-define-create-prd-v2.md`

**Execute:**
- Create PRD per template structure
- Requirements, acceptance criteria, scope
- Non-goals, constraints

**Grill:**
```
SPEC REVIEW

Grilling this spec...
- What requirements are missing?
- What's ambiguous?
- What will cause scope creep?

[Provide critical analysis]
```

**HITL Checkpoint:**
```
SPEC COMPLETE

1. Continue to next phase
2. Refine spec
3. Pause here

Select (1-3):
```

---

### PHASE 3: DIVIDE

**Template:** Read `docs/3-divide-generate-tasks-v2.md`

**Execute:**
- Generate tasks per template
- Parent tasks with subtasks
- Done-when criteria for each
- Output to TodoWrite

**Grill:**
```
TASK REVIEW

Grilling this task breakdown...
- What tasks are missing?
- What dependencies are hidden?
- What's underestimated?

[Provide critical analysis]
```

**HITL Checkpoint:**
```
TASKS COMPLETE

1. Continue to Deliver
2. Adjust tasks
3. Pause here

Select (1-3):
```

---

### PHASE 4: DELIVER

**Template:** Read `docs/4-deliver-execute-tasks-v2.md`

**If FIX (from Step 1):**
```
FIX DETECTED - Running impact assessment...

[Execute /fix protocol]
- Who calls this code?
- What depends on current behavior?
- What will break?
- Migration path?

[Present findings]
```

Then HITL:
```
IMPACT ASSESSMENT COMPLETE

1. Proceed with fix
2. Revise approach
3. Abort

Select (1-3):
```

**Execute:**
- Implement per template
- One subtask at a time
- Mark TodoWrite as complete per task
- Follow task execution rules

**Grill:**
```
IMPLEMENTATION REVIEW

Grilling this implementation...
- What edge cases are unhandled?
- What could break in production?
- What's the failure mode?
- Security concerns?

[Provide critical analysis]
```

**HITL Checkpoint:**
```
IMPLEMENTATION GRILLED

1. Clean - proceed to Prove
2. Issues found - need elegant solution
3. Ship without Prove

Select (1-3):
```

**If Option 2 (Issues):**
```
ELEGANT SOLUTION

Stepping back with full context...

Knowing everything now, what's the elegant solution?

[Provide redesigned approach]
```

Then HITL:
```
1. Implement elegant solution (restart Deliver)
2. Keep current implementation
3. Discuss further

Select (1-3):
```

---

### PROVE (Before Ship)

**Execute:**
```
PROVING IT WORKS

Demonstrating this works...

1. DIFF ANALYSIS
   - Behavior before: [describe]
   - Behavior after: [describe]
   - Files changed: [list]

2. TEST EVIDENCE
   - Tests run: [list]
   - Results: [pass/fail]
   - Coverage: [if applicable]

3. VERIFICATION
   - How to manually verify: [steps]
   - Expected outcome: [describe]
```

**If Destructive/External Operation:**
```
DESTRUCTIVE OPERATION DETECTED

Operation: [git push / sync / delete / deploy]

DRY RUN:
[Show what will happen]

1. Proceed
2. Abort
3. Modify

Select (1-3):
```

## HITL Checkpoints

- After each phase → User approves before continuing
- After grill → User decides: continue, refine, or pause
- Before destructive ops → Dry run + confirm
- Elegant solution → Only if issues found in grill
